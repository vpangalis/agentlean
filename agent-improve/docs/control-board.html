Validation stack
Four layers, one shared retry cap of three, accumulated feedback.
Not an agent. Deterministic checks and model-graded checks, in cheapest-first order.
Runs once, at the gate boundary — except layer 2a, which is middleware and runs every turn.
Each layer fires only if the previous passes.
The counter and the feedback live on the phase state, never in route scope, never per layer.
Never downgrade the coherence or constraint checks to keyword checks.
Layer 2b runs, but only at the gate, and reads the store the old write path filled. 7.1
Layers 2c and 2d do not exist. 2d is the reader the design means when it says the grader scans the computation results. 7.2
Gate review
Where the phase stops and hands control back to the Belt.
Not an agent. No model call. Builds the review payload and pauses.
The prebuilt approval middleware is banned here — two confirmed bugs would silently discard a Belt's correction.
It routes nothing. It presents the validated fields and stops.
A pause needs a live checkpointer, and resuming re-runs this node from its first line — so it must write nothing.
It logs and passes straight through. There is no pause in production code anywhere. 7.3
And no route that could answer one. An interrupt with no resume parks the case forever, which is why it was removed rather than left firing. 7.3 · 7.7
Gate apply
Writes the gate document and branches on your answer.
Not an agent. No model call — schema validation over the captured fields.
Two invariants run BEFORE the document is built, and both raise: every schema field must be referenced, and the metric entry must equal its mirrored scalars.
Approve ends the phase; reject returns to the planner carrying the Belt's reason.
Because resume re-runs the node, this write must be safe to perform twice.
It applies nothing, by design, until the gate card is built — the route does the write. 7.3
The route's write now uses the same assembly as the preview and merges rather than replaces — fixed at 90948de.

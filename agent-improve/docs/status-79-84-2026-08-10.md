# §79–§84 status in the v2.2 constitution — 2026-08-10

**§79 — LangGraph 1.2 native reliability** (source line 5787).
CLAUDE.md §3.6 mandates `TimeoutPolicy(run_timeout=45)` *"required on every
phase executor node"* and `error_handler=` *"required on every node with
external writes"*; `RunControl.request_drain()` for shutdown; custom Saga code
BANNED. Enforced by the no-go list and drift `pattern-4-custom-saga` → §3.6.
**Divergence:** `DeltaChannel` not adopted — beta API, deferred to §87 item 12.

**§80 — AgentMiddleware six hooks** (source line 2074).
CLAUDE.md §8 is a dedicated section; §8.1 names the five-middleware stack built
on *"the six `AgentMiddleware` hooks"* and states *"Prefer built-in middleware
wherever it exists"* — two of five are core. §8.6 records what is deliberately
not used. ARCHITECTURE.md §3.4 carries the design and ordering rule.

**§81 — `content_blocks`, not string parsing** (source line 2233).
CLAUDE.md §4.5 mandates `response.content_blocks`; string-indexing the raw
content field is *"a violation"*. Enforced by the no-go list and drift
`pattern-3` → §4.5. ARCHITECTURE.md correctly does not restate it — a rule, not
a design. **Note:** the rule is landed, but a live violation remains in code at
`upload/agent.py:107` (audit D3.4), uncovered by any §15 step. Code drift, not a
constitution gap.

**§82 — `ProviderStrategy` / `response_format=`** (source line 1668).
**This was the July audit's priority blocker; it is resolved.** §4.3 no longer
mandates `.with_structured_output()` — it now reads *"Never parse JSON from raw
LLM text"* and delegates: *"The mechanism is §4.6; this rule is the
prohibition."* §4.6 exists, scoping `response_format=` to agents and the
builder-style call to tools/middleware/validators. All four drift-registry rule
citations now resolve: `pattern-2`→§4.6, `pattern-3`→§4.5, `pattern-4`→§3.6,
`pattern-8`→§4.4. The contradiction — §4.3 mandating what the hook blocked,
while the hook cited a §4.6 that did not exist — is gone in both directions.

**§83 — Agent Skills SKILL.md spec** (source line 2804).
ARCHITECTURE.md §8.4: five SKILL.md under `skills/`, *"following the
agentskills.io standard"*, `allowed-tools` matching §8.2. CLAUDE.md §8.3 has the
rule side — three disclosure levels, `FilesystemBackend`, and the
`.claude/skills/` vs `agent-improve/skills/` split. On disk as five
`skills/dmaic-{phase}-phase/SKILL.md` (filename restored in `fe21816`).

**§84 — SkillsMiddleware / progressive disclosure** (source line 2948).
`bind_tools` appears **zero times** in ARCHITECTURE.md; the one CLAUDE.md hit is
the v2.1→v2.2 change table recording the move away from it. §3.3 builds the
executor with `create_agent`; §3.4 is the five-middleware stack including
`DMAICSkillsMiddleware` with three-level disclosure. Enforced by §4.4 and drift
`pattern-8`. **Divergence:** deepagents is not a dependency — `create_deep_agent`,
`RubricMiddleware`, `SkillsMiddleware` BANNED while pre-1.0 (§4.4, §8.6).

*Anchor note: the brief expected the middleware stack at §3.2. Numbering shifted
in the v2.2 rewrite — §3.2 is the subgraph, §3.3 the executor, §3.4 middleware.*

**Blockers: none from §79–§84.** The July audit's one Step-3.1 blocker is
unrelated and still stands — the canonical seven-tool set does not exist in
code, so `tool_args.py` cannot be written until the toolset is reconciled
(Delta 1c/1d, D3.5). That is what Step 3.0 exists to resolve.
